# Noche del 2026-11-25

Una línea por tarea: qué se hizo y qué falló.

- **T0 · licencia de los datos.** ADR-0022 (propuesto): `license_class`/`licensee` en el modelo,
  conectores como plugins, instancias `public`/`clients`/`third_party`, nivel por feed; guarda y
  test de «la instancia pública no guarda nada restringido» con conectores sintéticos. ADR-0017
  aceptado (Zernio). Falló: las páginas de la EUVD no cargaban, así que su licencia queda SIN
  VERIFICAR y no se activa; INCIBE y Chainguard/Wolfi no se reclasifican (las citas no lo permiten).
- **T2 · modelo de datos y migraciones.** El borrador SQL pasa a modelo de SQLAlchemy 2.x
  (`src/vs/model/`) con una migración inicial de Alembic (arriba y abajo, tipos ENUM incluidos). Los
  tests `db` crean una base desechable en PostgreSQL 17, suben y bajan la migración, comprueban que
  modelo y migración no divergen, que el CHECK de licencia vive en la base y que las seis consultas
  de métricas dan lo esperado con datos sintéticos. En CI corren con un servicio `postgres:17`.
  `schema-draft.sql` se retira. Falló: un `inspect.py` olvidado en `local/tmp/` tapaba el módulo
  estándar; los scripts de trabajo van ahora en un subdirectorio por tarea.
- **T3 · conectores abiertos.** Conectores de cvelistV5, CISA KEV, EPSS, GHSA y OSV sobre la
  interfaz de plugins, con transporte HTTP inyectable y un ejecutor que deja una fila de
  `source_run` por ejecución. Fail-closed: timeout, HTTP 5xx, dato roto, lectura incompleta o dato
  más viejo que el umbral dan UNKNOWN y ningún registro. Normalización a `vulnerability`,
  `affected_product` y `signal` con las dos marcas de tiempo y la carga inicial marcada `baseline`.
  OSV aplica la licencia por fuente: fuera Chainguard/Wolfi, `share_alike` en Ubuntu y Alpine, y
  no lee fuentes sin licencia comprobada. Fixtures pequeños y sin red. Falló: la EUVD seguía caída
  y la política IPR de ENISA no cubre bases de datos, así que la EUVD queda fuera.
- **T4 · reglas A/B/C y carga inicial.** Motor determinista en `src/vs/rules/` (CMP-021):
  `impact_class` por CWE, CVSS (v2, v3.x, v4.0) y SSVC; `producto_expuesto` por vendor/product,
  alias, prefijo CPE y purl; E1–E4, con E5 solo como interfaz; elegibilidad del §5.1 con N
  configurable; `rule_evaluation` y `alert_level_history`. El nivel publicado solo sube (la IA no lo
  baja; solo un acto manual con autor y motivo). El nivel se calcula por feed con lo que su
  audiencia puede recibir: el esbozo de `rights.py` pasa a usar el motor. Tests con listas de
  fixture ficticias: carga inicial y fuente nueva dan 0 alertas, DoS con exploit no es B, una USN de
  kernel sintética con 300 CVE solo alerta las de KEV, y monotonía con hypothesis. Falló: nada
  bloqueante; quedan abiertas la relación nombre↔cuenta de GitHub para E4 y el nivel del feed
  completo para CVE no elegibles.
- **T5 · feed OSV firmado.** `src/vs/feed/` (CMP-022, CMP-023): registro OSV 1.9.2 por CVE con
  `id` estable `VS-CVE-…` y la extensión `database_specific.vuln_sentinel`; rangos de CVE 5 y GHSA
  convertidos a eventos OSV solo cuando la conversión es exacta; feed completo y de alertas por
  audiencia; índice de cambios con cursor `(modified, id)`, 1.000/5.000 por página, horas selladas
  inmutables y `410` con el enlace al snapshot más allá de 30 días. `schema/feed-1.0.0.json`.
  Firma JWS detached ES256 (RFC 7797) tras la interfaz `Signer` (`LocalDevSigner`; `KeyVaultSigner`
  solo interfaz), JWKS de ejemplo y `examples/verify/` con openssl y Python, probado de punta a
  punta. Falló: el esquema oficial de OSV 1.9.2 no admite el prefijo `VS-` en `id` ni el ecosistema
  `Generic` del ejemplo del plan; el registro valida todo lo demás y queda como pregunta para Juan.
- **T6 · API de solo lectura.** FastAPI en `src/vs/api/` (CMP-002) sobre el publicador de T5:
  índice «head» de `all` y `alerts` con cursor, `latest.json`, registros con ETag igual al hash y
  `304`, resumen de un día cerrado, JWKS y métricas leídas de `metric_daily`, incluido el coste
  frente a donaciones. Cada documento tiene su `.jws`. Solo `GET`; la API pública no arranca con un
  publicador que admita `restricted`; con `donations.enabled=false` no sale ningún dato de
  donaciones. `/admin/*` es un esqueleto que valida el JWT de Access (RS256, `iss`, `aud`, vigencia)
  y cierra si no hay configuración. Falló: la firma del índice «head» y de `latest.json` depende de
  la hora de la petición, así que su `.jws` solo casa si ambos salen del mismo instante (pregunta
  abierta); SQLite en memoria necesitó una conexión única para probar el lector SQL.
- **T7 · conectores de exploits.** Metasploit (tipo de módulo: `exploit/` frente a
  `auxiliary/dos`), Exploit-DB (solo metadatos: identificador, tipo, plataforma y fecha),
  PoC-in-GitHub (commits de la API y JSON por CVE, sin clonar) y búsqueda de GitHub solo para
  candidatos, con 30 búsquedas/min con token y tope de candidatos (CMP-024). Heurísticas
  `poc_suspicious` sobre metadatos y la API de contenidos, sin ejecutar nada: binarios, blobs u
  ofuscación, `curl|sh` y descargas ajenas, cuenta de menos de 30 días, README sin código y fork;
  un PoC sin inspección completa queda sin decidir, nunca limpio. Fail-closed y `source_run` como
  en T3. Integración con las reglas: un módulo DoS no da B; `exploit/` da E1 y Exploit-DB `remote`
  da E2. Falló: el plan no fija N KB para los blobs ni la lista de dominios de descarga permitidos
  (valores por defecto y pregunta abierta); E4 con un repositorio sin inspeccionar sigue contando
  en las reglas de T4 (fuera de esta tarea; pregunta abierta).
- **T8a · portal.** `web/` con Vite, React, Tailwind y shadcn/ui con sus gráficas (ADR-0023),
  versiones exactas y `package-lock.json`. Un solo fichero de tokens: A, B y C con el mismo color en

  componentes en verde; servidor de fixtures en `tests/portal_fixture.py`; job `web` en la CI.
  Falló: la prueba de humo con Playwright y axe no pudo correr en local (a Chromium le faltan
  librerías del sistema y no hay permisos para instalarlas); queda para la CI. La CLI de shadcn
  escribió imports a un paquete `cn` inexistente y se corrigieron a mano.
- **T9 · infraestructura como código, sin desplegar.** `infra/` en Bicep por módulos: VNet propia
  con subredes delegadas y zonas DNS privadas; entorno ACA solo Consumption e interno; API con

- **T10 · agente investigador con modelo simulado.** `src/vs/agent/` (CMP-031): bucle propio con
